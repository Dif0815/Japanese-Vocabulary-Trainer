# Japanese Vocabulary Trainer — Learning Statistics popup layout
#
# Uses the same line-definition syntax and dynamic layout behavior as
# config/word-popup-layout.txt. Sections use the CSV type value; [fallback]
# is used when no exact type section exists.
#
# ja_asked       = number of Japanese -> English translation questions asked
# ja_correct     = number of Japanese -> English translation questions answered correctly
# ja_wrong       = number of Japanese -> English translation questions answered incorrectly
# en_asked       = number of English -> Japanese translation questions asked
# en_correct     = number of English -> Japanese translation questions answered correctly
# en_wrong       = number of English -> Japanese translation questions answered incorrectly
# last_added     = timestamp when the word was first initialized in learning data
# last_ja_correct = timestamp of the most recent correct Japanese -> English answer
# last_en_correct = timestamp of the most recent correct English -> Japanese answer
# ja_wrong_since_correct = wrong Japanese -> English answers since the last correct answer
# en_wrong_since_correct = wrong English -> Japanese answers since the last correct answer
# ja_review_active = whether Japanese -> English is currently in Needs Review
# ja_review_asked = answers given while recovering Japanese -> English review
# ja_review_correct = correct answers while recovering Japanese -> English review
# en_review_active = whether English -> Japanese is currently in Needs Review
# en_review_asked = answers given while recovering English -> Japanese review
# en_review_correct = correct answers while recovering English -> Japanese review
#
# The same field availability rules as config/word-popup-layout.txt apply here;
# any field supported by the Word Popup field mechanism is supported here as well.
# Learning-statistic fields are persistent browser data, not CSV columns.
# Empty values are ignored by the normal layout engine.
#
# ------------------------------------------------------------
# DATE / TIME FORMATTING
# ------------------------------------------------------------
# The optional `format` parameter can be added to a date/time field:
#
#   format=dd.mm.yyyy
#       date only, for example 21.08.2026
#
#   format=hh:mm
#       time only, for example 14:35
#
#   format=dd.mm.yyyy hh:mm
#       date and time, for example 21.08.2026 14:35
#
# Examples:
#
#   line=6; label=Added; db=last_added; format=dd.mm.yyyy; under=true
#   line=6; label=Added time; db=last_added; format=hh:mm; under=true
#   line=6; label=Last correct; db=last_ja_correct; format=dd.mm.yyyy hh:mm; under=true
#
# `format` is optional. If it is omitted, the raw stored value is displayed.
#
# Supported format strings are exactly:
#   dd.mm.yyyy
#   hh:mm
#   dd.mm.yyyy hh:mm
#
# An invalid/unsupported format string produces a warning in the central
# configuration-warning system. The application continues to work and the
# raw database value is displayed as the fallback.
#
# ------------------------------------------------------------
#
